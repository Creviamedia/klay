# Performance experiments — 2026-11-17

Base: production source commit `9270641e5184da43004d9d41999d92cb81182b38`.
Lighthouse mobile, installed Chromium, serial runs against local production SSG.
Local scores are lab measurements, not live deployment verification.

| Experiment | Baseline → candidate | Decision | Evidence / limitation |
| --- | --- | --- | --- |
| Split Sentry SDK from the entry bundle | Gzip-served performance 74 → 72; FCP 1.1s → 1.1s; TBT 220ms → 220ms; LCP 6.2s → 7.4s | Reverted | Production config enables Sentry, so the SDK still downloads immediately. Smaller entry alone did not improve representative performance. |
| Remove duplicate hero video poster and lazy-load responsive jurisdiction card images | Gzip mobile performance 74/75 → 87; LCP 6.2/7.1s → 3.5s; CLS 0 throughout | Retained | Initial mobile image transfer eliminated 533,116 bytes of below-fold images; visible 46,111-byte responsive hero retained. Accessibility 95, Best Practices 100, SEO 100. |
| Same SDK split, uncompressed server | Performance 58 → 71; TBT 270ms → 110ms | Not used for deployment decision | Uncompressed delivery differs from production compression and exaggerated entry transfer costs. |

Earlier local Python-server runs were invalid because parallel module requests reset connections,
triggering reloads and layout shifts. They are excluded. Initial live runs warned of slow host CPU;
those snapshots do not establish a reliable before/after result.

Mobile resource inspection found the hidden desktop video poster (~160 KiB) downloading alongside
the visible responsive hero image (~46 KiB). The targeted combined correction is retained based on the measured LCP and transfer reduction. Browser smoke confirmed desktop video playback, lazy images after scrolling, intact layout and no page errors on mobile/desktop. Performance 95 remains unachieved; live deployment verification is still required.
